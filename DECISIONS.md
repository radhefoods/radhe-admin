# Decisions

Design and technical decisions of the Radhe Foods admin panel, with their reasons. Keep this file current. The conventions every page follows are in `CONTRIBUTING.md`.

## Decided at the start (2026-10-04)

The owner asked for a plan first and then the implementation, and for questions instead of assumptions. Nothing blocked the start, so these were decided and reported; any of them can be changed.

| Topic            | Decision                                                                                                                                                                            |

## Architecture

**Session.** Cookies travel with every call (`credentials: 'include'`). On `401 AUTH_TOKEN_INVALID` the refresh endpoint is asked once and the call is repeated; `AUTH_REFRESH_INVALID`, `AUTH_SESSION_REVOKED` and `ADMIN_ACCOUNT_DISABLED` end the session (`src/lib/api/session.ts`).

**Refreshes never run side by side.** Refresh tokens rotate, and a refresh that loses the rotation is answered with cleared cookies. Two tabs refreshing at once would therefore sign the admin out. Calls of one tab share one refresh; tabs of one browser take turns through the Web Locks API, and a tab that waited for another tab's refresh does not refresh again.

**A session that ends keeps the work.** When the session ends while the admin is working (12 hours without use, 72 hours in any case, a role change), the page stays as it is and a sign-in opens over it, with the email fixed. A half-filled form is still there afterwards. Signing in as someone else clears everything that was loaded.

**Forced password change.** `403 ADMIN_PASSWORD_CHANGE_REQUIRED` from any call, or `mustChangePassword` on the admin, routes to the change-password screen; nothing else renders until it is done.

**Permissions.** `can()` mirrors the API's rule exactly: `*`, `orders.*`, and `read` and `manage` independent. Navigation entries and pages need the read permission; buttons that change data stay visible, disabled, with a hint that names the missing permission. A `403 ADMIN_PERMISSION_DENIED` makes the panel ask the API again who the admin is, because the role may have been edited. The API enforces everything anyway.

**Status transitions come from the API.** The buttons of a cargo and of an order are exactly `allowedStatuses`; `canCancel`, `canMove`, `canActivate`, `canRecordCash`, `canWaive` and `refundable` decide the rest. The panel's own tables of the documented transitions (`src/lib/status/transitions.ts`) only order the steps (next, back, aside) and are checked against the documentation by a test.

**Money.** Integer cents end to end. Amounts are printed and read digit by digit (`src/lib/format/money.ts`); no float touches a price. Both ways of writing a decimal are understood (`19.99`, `19,99`, `1.234,56`).

**Time.** The API speaks UTC; the business thinks in German time. Every moment is printed in `Europe/Berlin` whatever the device is set to, and every typed time is read as German time and sent with its offset, across the changes to and from summer time (`src/lib/format/dates.ts`, tested for both nights). The payment deadline shown before a confirmation is computed the way the API computes it: the end of today plus N days in Germany.

**Errors.** `ApiError` carries the code, typed details and the request id. Each documented code has the panel's own sentence (`src/lib/api/error-text.ts`; a test checks that none is missing). An unexpected error also shows the API's message and the request id. A code the panel does not know (a newer API) is shown as a general error and kept in `rawCode`.

**Lists live in the address.** Filters, search, sort and page are query parameters, checked against what the API accepts before they are sent on. A filtered list can be bookmarked and survives the back button.

**Cursor lists have no total.** Customers, orders, returns, refunds, invoices, notifications and announcements are paged by cursor; the panel says how many rows it shows and offers "Load more". Products, cargos and cargo products have pages and totals.

**Bulk actions work like the API.** The API changes "all orders of the cargo except the ones named" (`excludeOrderIds`). So the orders of a cargo are all ticked, and unticking leaves one out. For this the panel loads every order of the cargo (in pages of 100, up to 2,000). Moving orders to another cargo takes all movable ones: the API has no exceptions there, and the confirmation says so.

**Payment activation in batches.** The API activates 100 orders per request; the panel asks again while orders remain and stops if a request activates nothing, so a refusal can never loop.

**Confirmations.** Every destructive or money-moving action restates what will happen with the real numbers of the API before it runs. The keyboard focus starts on "cancel" and Enter never confirms by accident. Cancelling a cargo needs its code typed.

**Optimistic updates only where a failure is harmless.** The switch that makes a product orderable in a cargo answers at once and steps back if the API refuses. Nothing that moves money or status is optimistic.

**Unsaved changes.** A form that was changed asks before the tab closes or a link inside the panel is followed. The browser's back button is not intercepted: Next.js offers no supported way.

**Uploads.** `multipart/form-data` through `XMLHttpRequest`, because `fetch` cannot report upload progress, with the same session handling as every other call.

**Invoice PDFs** are fetched with the session and shown from a local blob: a plain link would not carry the session's refresh. The viewer offers "open in a new tab" and "download" as well, for phones and browsers that show no PDF inside a page.

**Admin names.** Records of the API carry an admin's id only. Names come from the team list, which needs `admin_users.read`; without it the panel shows the last characters of the id.

**Content security policy.** Every page gets a policy with a fresh nonce (`src/proxy.ts`): only the panel's own scripts run, and the browser only talks to the API. Inline styles are allowed because the positioning of menus and dialogs sets style attributes. The email preview of an announcement is shown in a frame that can run nothing.

**No search engine.** `noindex` in the metadata, in an `X-Robots-Tag` header and in `robots.txt`.

## What the API cannot do, and what the panel does instead

| Missing in the API                                                                        | In the panel                                                                                                                                                                                                                                                                                                                                                        |
| ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Reports and statistics (section 19: not built)                                            | The start page uses the attention overview, the cargo overview and the order and payment summaries per cargo.                                                                                                                                                                                                                                                       |
| Free-text search over orders and customers                                                | The global search (`/`) combines what exists: an order by its exact number or the customer's full email, a customer by the beginning of the email, a product by words, a cargo by its code.                                                                                                                                                                         |
| Totals and sorting on cursor lists                                                        | Newest first, "Load more", the number of rows shown.                                                                                                                                                                                                                                                                                                                |
| Bulk actions on a free selection of orders                                                | Per cargo with exceptions, as the API works. Moving takes all movable orders.                                                                                                                                                                                                                                                                                       |
| Finding an invoice by its number                                                          | Documents are found by the number of their order or by customer.                                                                                                                                                                                                                                                                                                    |
| Self-service change of the authenticator, and recovery codes                              | The profile explains it: an admin with the Team permission resets the two-factor, then the admin enrols again at the next sign-in. Someone with that permission can reset their own on the Team page (the API allows it): that is how a sole owner moves to a new phone while still signed in. A lost phone still locks a sole super admin out; see the open items. |
| An invitation email for a new admin                                                       | The temporary password is generated in the browser, shown once and handed over by the inviting admin.                                                                                                                                                                                                                                                               |
| Names on records (`adminId`, `customerId` only)                                           | Names are looked up when the viewer may read them; otherwise a short id, or the order number.                                                                                                                                                                                                                                                                       |
| Telling customers when the delivery days of a cargo change                                | Not offered: changing the days sends nothing. Announcements reach only customers who opted in to news.                                                                                                                                                                                                                                                              |
| A payment status of a cargo (the concept's "payment active", "payment remaining")         | Computed from the cargo's payment summary.                                                                                                                                                                                                                                                                                                                          |
| Editing a customer's data, or the items and prices of an order                            | Read-only. Only the delivered quantity of an order line can be corrected.                                                                                                                                                                                                                                                                                           |
| A flag that says whether Stripe is connected                                              | Known per order (`canPayOnline`, `refundable.stripePossible`); the panel says "online payment is not set up" there and on `503 PAYMENTS_NOT_CONFIGURED`.                                                                                                                                                                                                            |
| An audit log                                                                              | The histories the API keeps per record (cargo, order, return, refund, ordering decisions) are shown.                                                                                                                                                                                                                                                                |
| "The super admin is the only one who manages roles" (the prompt)                          | The API gates roles by `roles.manage`; the panel follows the API.                                                                                                                                                                                                                                                                                                   |
| Progress of an announcement in the list (only on the record)                              | The list shows the subject, what it is about and whether it was cancelled; the numbers per channel and status are on the announcement's page.                                                                                                                                                                                                                       |
| Ids on the overdue payments of a customer's ordering state (numbers only)                 | The order number leads to the order through the order list's filter; the invoice number is shown as text.                                                                                                                                                                                                                                                           |

| That changing a role's permissions signs its admins out (not documented)                  | The confirmation names the admins and says they "may have to sign in again".                                                                                                                                                                                                                                                                                        |
